### What must remain consistent when loading a paged KV cache?

**Card:** `attention-paged-kv-addressing` · **type:** `constraint` · **evidence:** `source_observed` · **status:** `candidate_only` · **axes:** `cache_layout`, `implementation_contract`

Source-observed candidate — the cited implementation exists; no performance preference is implied.

#### Machine match

- `operator_families`: `attention_decode_paged`, `mla_attention`, `chunked_prefill`
- `target_languages`: `triton`, `flydsl`, `gluon`
- `requires`: `paged_kv`

#### Use when

- KV positions are logical sequence positions mapped through a per-request page table.

#### Try

- Resolve each logical token through its block-table entry and its offset within the page; preserve the independent K/V cache strides.
- Distinguish a compute tile from a cache page: the general path may need multiple page-table lookups, while TILE_SIZE == BLOCK_SIZE enables a specialized path.
- Validate ragged sequence lengths, nontrivial block-table strides and the final partial page against the actual cache producer.

#### Why this is a candidate

- The unified Triton kernel has distinct TILE_SIZE == BLOCK_SIZE and general page-lookup paths, with explicit K and V strides.

#### Keep as alternatives

- Use the general paged load path before specializing page-aligned tiles.

### How must tiled forward attention preserve masking and online softmax normalization?

**Card:** `attention-online-softmax-mask` · **type:** `semantic` · **evidence:** `source_observed` · **status:** `candidate_only` · **axes:** `attention_semantics`, `numerical_contract`

Source-observed candidate — the cited implementation exists; no performance preference is implied.

#### Machine match

- `operator_families`: `attention_prefill_fmha`, `gqa_mqa_attention`
- `target_languages`: `triton`, `flydsl`, `gluon`

#### Use when

- The operation is scaled dot-product forward attention, with an explicit causal or noncausal contract.

#### Try

- Carry the running maximum, exponential sum and output accumulator together across KV tiles; rescale prior contributions when the maximum changes.
- Apply sequence-tail and causal masks to scores before exponentiation; a zero-filled invalid key is not an excluded softmax position.
- Keep QK scale, exponential base and accumulator precision consistent through the update and any final normalization.

#### Why this is a candidate

- The Triton prefill kernel updates m_i, l_i and acc jointly, masks invalid scores with negative infinity, and casts probabilities to the value dtype before the PV dot.

#### Keep as alternatives

- Retain a straightforward unfused reference for the same mask and scale contract.

### When splitting KV work, what information must the merge preserve?

#### Machine match

- `operator_families`: `attention_decode_paged`, `mla_attention`, `context_parallel_attention`
- `target_languages`: `triton`, `flydsl`, `gluon`

#### Use when

- A long KV sequence leaves too few independent query/head workgroups, or partial attention outputs already exist.

#### Try

- Try multiple KV partitions together with an explicit partial-output and normalization-statistics layout.
