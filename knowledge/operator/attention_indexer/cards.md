How to read a card:
- **Evidence** — `reported`: an upstream PR or benchmark reported an outcome (not reproduced here; the outcome
  line says what was reported). `source-only`: observed in shipped source or configs; it shows what an
  implementation does, not that it wins. Treat both as hypotheses and measure on your own kernel and shapes.
- **Applies** — the languages/dtypes/GPUs the card was derived from. For a kernel in another language the card is a
  porting idea, not a recipe.
- `constraint` cards are correctness or validity rules: check them before trusting a speedup.

Design traits that some cards require (`requires`):
- `paged_kv` — The design resolves logical KV positions through a physical page table.
- `distributed_candidates` — Top-k candidates are gathered from multiple ranks in a declared ownership order.

<a id="indexer-dcp-merge-ownership"></a>
### How does DCP top-k merge preserve rank ownership and physical KV slots?

`indexer-dcp-merge-ownership` · constraint · evidence: **source-only** · applies: lang flydsl; requires `distributed_candidates`

**When:** The selected implementation merges rank-major candidate scores for qlen=1 decode.
**Try:**
- Keep gathered candidate columns in rank-major order: column // local_k identifies the owner rank.
- Pad unused score candidates with negative infinity, not zero; another rank's plane has no local index liveness signal.
- Provide int32 block tables, indices, indptr, staging and counts with the validated capacity; convert the owned winning logical tokens to physical cache slots.
- Respect the wave64 and qlen=1 restrictions and warm each compiled shape before graph capture.
**Why:** The merge API documents positional ownership, and its validator checks dtype, dimensionality, rank range and output capacities.
**Alternatives:** Keep candidate gathering, global selection and rank-local packing as explicit stages while validating ownership.
**Limits:**
- This merge does not implement the all-gather itself.
- The decode-only row/indptr contract cannot be assumed valid for arbitrary prefill queries.
**Reported:**
- gain reported: The fused owned-slot DCP merge has a reported single-operator benefit; real multi-GPU all-gather and full-decode attribution remain unvalidated.
**Read more:** [README.md](README.md)

### Which FP8 format conversions does the contiguous FlyDSL MQA logits path require?

`indexer-fp8-architecture-format` · constraint · evidence: **source-only** · applies: lang flydsl; gfx gfx942/gfx950

**When:** The selected path is flydsl_fp8_mqa_logits on gfx942 or gfx950.
**Try:**
- On gfx950, respect the wrapper's native e4m3fn Q/KV requirement.
- On gfx942, keep the FN-to-FNUZ byte interpretation, negative-zero handling and compensating scale factor together; each FN operand contributes a factor of two.
- Retain the wrapper's contiguous Q/KV materialization and logical-rank restoration for single-token scales and weights.
**Why:** The host wrapper explicitly distinguishes the two architectures and adjusts kv_scales consistently with operand recasting.
**Alternatives:** Use a native-format path or an explicit higher-precision reference before attempting a byte reinterpretation.
**Limits:** The conversion is specific to the stated e4m3 formats and implementation; it is not a generic FP8 cast rule.
**Reported:**
- mixed: The FlyDSL wrapper and format checks belong to the implementation reviewed in PR #4538; the mixed reported comparisons do not isolate format conversion or score semantics.

### Which packed payload, scale and tile constraints accompany paged MXFP4 scoring?

`indexer-paged-mxfp4-layout` · constraint · evidence: **source-only** · applies: lang flydsl; requires `paged_kv`

**When:** The candidate targets build_pa_mqa_logits_fp4_module and its packed cache representation.
**Try:**
- Keep packed Q/KV bytes, E8M0 scale indexing and physical block-table addressing aligned; head_dim is not the byte width of a packed row.
- Enforce head_dim multiples of 128, head-count/MFMA alignment and page/block tile divisibility from the builder.
- Preserve the per-K-tile Q and KV scale application inside scaled MFMAs rather than substituting one scale for a whole row.
**Why:** The builder separately derives packed data and KV-scale strides and applies scale_a/scale_b for each compute tile.
**Alternatives:** Use explicit unpack/dequant scoring as a reference for the same logical cache.
**Limits:**
- A contiguous FP8 score kernel cannot consume this cache by changing dtype alone.
- Builder existence is not proof that the current host route enables this variant.

### What must a top-k implementation preserve beyond score values?

`indexer-topk-row-index-contract` · constraint · evidence: **source-only** · applies: lang flydsl

**When:** A per-row selector converts scores into the indices consumed by sparse attention.
**Try:**
- Validate effective row lengths, k, output index dtype and strides, and optional score outputs.
- For packed rows, preserve the convention that output indices are relative to row_starts, while plane_width bounds the launch geometry.
- Check tie behavior and padding explicitly for the selected implementation; a stable parameter in a wrapper signature is not proof that every fast path enforces stable ordering.
- For graph capture, initialize the split path's stream-local arrival state on the capture stream as documented by the wrapper.
**Why:** The host wrapper validates tensor signatures, has packed-row inputs, and dispatches between one-workgroup and split implementations.
**Alternatives:** Compare against a reference top-k with an explicitly stated tie convention and row bounds.
**Limits:**
- Score closeness alone does not prove index equivalence.
- Allocated row width and effective per-request context length are separate quantities.

<a id="indexer-window-and-clean-output"></a>
### Who initializes logits outside each query's valid window?

`indexer-window-and-clean-output` · constraint · evidence: **source-only** · applies: lang flydsl/triton

**When:** The score buffer may be consumed by top-k over a larger allocated row.
**Try:**
- Preserve the half-open [cu_starts, cu_ends) validity interval and mask the tail.
- With clean_logits=True the FlyDSL kernel writes negative infinity outside the window; with False the caller owns the skipped positions.
- Never feed uninitialized or stale out-of-window values into a selector that does not independently honor the same bounds.
**Why:** The public FlyDSL API makes output cleaning an explicit behavior flag rather than an unconditional prefill of the output tensor.
**Alternatives:** Initialize invalid scores explicitly, or use a selector with verified matching row bounds.
**Limits:** Skipping output cleaning is only valid when the downstream validity contract excludes those positions.
**Reported:**
- gain reported: The PR reports lower operator latency after fusing invalid-logit initialization on gfx942.
**Read more:** [README.md](README.md)

### How does MiniMax block scoring differ from per-token MQA logits?

`indexer-minimax-page-max-score` · semantics · evidence: **source-only** · applies: lang flydsl; gfx gfx950

**When:** The task is the MiniMax-M3 decode page-score implementation on gfx950.
**Try:**
- Compute a maximum over the tokens in each page for each query/head feature, respecting the per-query causal cutoff.
- Keep the source's FP8-cache-to-BF16 widening before the BF16 dot when Q is BF16; rounding Q down changes the ranking contract.
- Match the page layout, supported dimensions and output score layout before choosing decode or prefill tiling.
**Why:** The source uses token-major MFMA fragments so much of the page maximum is reduced within registers, with final lane reductions.
**Alternatives:** Use a reference that widens K to Q precision, scores each token and takes the page maximum.
**Limits:**
- This page-max score is not the DeepSeek weighted-ReLU head sum.
- The cited geometry is a gfx950 implementation, not a universal 128-token-page recommendation.

<a id="indexer-mqa-score-semantics"></a>
### What does the DeepSeek-style MQA indexer compute before top-k?

`indexer-mqa-score-semantics` · semantics · evidence: **source-only** · applies: lang triton/flydsl/gluon

**When:** The workload uses weighted, rectified MQA logits over a per-query KV window.
**Try:**
- Preserve logits[m,n] = sum_h ReLU(dot(Q[m,h,:], K[n,:]) * kv_scale[n]) * weights[m,h].
- Keep rectification before the head reduction and preserve the signed head weights and KV scale placement.
- Validate selected indices after top-k as well as score error; small score changes near the cutoff may change the sparse attention input.
**Why:** The Triton score kernel performs the dot, KV scaling, ReLU, per-head weighting and reduction without softmax or a value projection.
**Alternatives:** Use a direct FP32 scoring expression and top-k over the same valid window as a reference.
**Limits:** This is not ordinary softmax attention and not the MiniMax page-max scoring contract.
**Reported:**
- mixed: The FlyDSL wrapper and format checks belong to the implementation reviewed in PR #4538; the mixed reported comparisons do not isolate format conversion or score semantics.
**Existing implementations:** flydsl: The host API supplies the same Q, KV, scales, weights and row windows to explicitly selected kernel variants.
