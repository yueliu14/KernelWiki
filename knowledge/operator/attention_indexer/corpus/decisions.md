### What does the DeepSeek-style MQA indexer compute before top-k?

**Card:** `indexer-mqa-score-semantics` · **Type:** `semantic` · **Evidence:** `source_observed`

**Axes:** `score_semantics`, `numerical_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>triton</code>, <code>flydsl</code>, <code>gluon</code>

#### Use when

- The workload uses weighted, rectified MQA logits over a per-query KV window.
- Reviewed PR evidence covers FP8 Q/KV on gfx942 and gfx950 with H=32 or H=64; other dtypes and head counts were not reported.

#### Try

- Preserve logits[m,n] = sum_h ReLU(dot(Q[m,h,:], K[n,:]) * kv_scale[n]) * weights[m,h].
- Keep rectification before the head reduction and preserve the signed head weights and KV scale placement.
- Validate selected indices after top-k as well as score error; small score changes near the cutoff may change the sparse attention input.
- When comparing latency, use the same clean_logits setting in candidate and reference: in one gfx942 FP8 FlyDSL case (Sq=Skv=4096, H=64, mfma_r2_w4) fused clean_logits initialization was reported at 191.4 us versus 210.4 us with separate output initialization.

#### Rationale

- The Triton score kernel performs the dot, KV scaling, ReLU, per-head weighting and reduction without softmax or a value projection.

#### Keep as alternatives

- Use a direct FP32 scoring expression and top-k over the same valid window as a reference.

#### Other implementations

- **flydsl** — The host API supplies the same Q, KV, scales, weights and row windows to explicitly selected kernel variants. [aiter_b3ad6c46:src_744823ffb69cb339](source_evidence.md#aiter_b3ad6c46-src_744823ffb69cb339)

### Who initializes logits outside each query's valid window?

**Card:** `indexer-window-and-clean-output` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `score_semantics`, `selection_contract`, `implementation_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>flydsl</code>, <code>triton</code>

#### Use when

- The score buffer may be consumed by top-k over a larger allocated row.

#### Try

- Preserve the half-open [cu_starts, cu_ends) validity interval and mask the tail.
- With clean_logits=True the FlyDSL kernel writes negative infinity outside the window; with False the caller owns the skipped positions.
- Never feed uninitialized or stale out-of-window values into a selector that does not independently honor the same bounds.

#### Rationale

- The public FlyDSL API makes output cleaning an explicit behavior flag rather than an unconditional prefill of the output tensor.

#### Keep as alternatives

- Initialize invalid scores explicitly, or use a selector with verified matching row bounds.

#### Try

- Compute a maximum over the tokens in each page for each query/head feature, respecting the per-query causal cutoff.
- Keep the source's FP8-cache-to-BF16 widening before the BF16 dot when Q is BF16; rounding Q down changes the ranking contract.

#### Keep as alternatives

<a id="relu-on-mfma-accumulator-integer-max"></a>
### Can a ReLU on f32 MFMA accumulator output be lowered to one integer max instead of a canonicalize plus a float max?

**Card:** `relu-on-mfma-accumulator-integer-max` · **Type:** `performance_candidate` · **Evidence:** `reported_experience`

**Axes:** `compute_schedule`, `numerical_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>gluon</code>, <code>triton</code>
- `gfx`: <code>gfx950</code>

#### Use when

- The kernel applies max(x, 0) to f32 matrix-core (MFMA) output before scaling or reduction
- The ISA shows two v_max_f32 per element after the MFMA: LLVM does not treat MFMA results as canonical, so it inserts a canonicalize before the real max
- Epilogue VALU work sits in the main loop alongside MFMA, so removing VALU instructions can shorten the iteration
- Only finite accumulator values need correct ReLU semantics (no NaN propagation contract)

#### Try

- Inspect the compiled ISA around each ReLU for a canonicalize v_max_f32 followed by the real max
- Bitcast the f32 value to int32, take an integer max with 0, and bitcast back to f32 (one v_max_i32)
- Apply the rewrite at every ReLU site of the path (prologue, main loop, tail and any fused extra rows), not only the steady-state loop
- Recount main-loop VALU, VGPRs, occupancy and spills from the ISA after the change
- Re-run correctness and selected-index parity, since scores feed top-k

#### Rationale

- A negative IEEE f32 has its sign bit set, so it is a negative int32 and an integer max with 0 maps it to +0.0
- Non-negative f32 values order the same as their int32 bit patterns, so non-negative inputs pass through unchanged
- One v_max_i32 replaces a canonicalize v_max_f32 plus the max, freeing VALU issue slots in an MFMA-interleaved loop

#### Keep as alternatives

- Keep the float max where the compiler already emits a single max or the epilogue is off the critical path
- Fold the ReLU into the weight scale as sign(w) * max(o*|w|, 0); in the recorded attempt the engineer reported it de-packed the multiplies, raised VALU and VGPRs, and left speed flat

**Review: unreviewed**.
PR provenance and reported effects have not been reviewed for this direction; effect confidence is unknown.

#### Reported experience

Raw run artifacts are not published here. Historical reports have not been reproduced for this corpus. Outcomes are scoped to the conditions below; a combined result does not isolate each action's effect.

- **beneficial** — Replacing the float ReLU on MFMA output with an int32 max on its bits removed the extra canonicalize max per element. The step beat its parent at unchanged register use and occupancy, and was built on in later rounds.
  Conditions: fp8_e4m3 paged MQA-logits indexer decode on gfx950 (MI355X), Gluon kernel with ReLU, per-head weight scale and row reduction on MFMA f32 output, including fused second query rows decode M=6-18; the engineer's buckets were batch 2-3 at contexts from 104k to 418k tokens and all improved the rewrite was applied at every ReLU site (prologue, main loop, tail) of one gfx950 preshuffle code path the engineer's ISA count reported main-loop VALU 276 -> 221 with MFMA count, VGPRs (129), occupancy (3) and spills (0) unchanged MFMA output in this kernel is finite, so the NaN difference of the integer max did not apply; correctness, parity and graph replay passed

  Sources: Private validation; raw artifacts are not published.

#### Limits

- NaN handling differs from the float max; use the rewrite only where accumulator output is known finite
- -0.0 becomes +0.0, which matches max(-0.0, 0.0) only up to the sign of zero
- Recorded on one fp8_e4m3 indexer decode step on gfx950; the gain depends on epilogue VALU being on the critical path
- Rewrites that remove the canonicalize by reshaping the math can break packed multiplies and raise VGPRs, so recheck the ISA
