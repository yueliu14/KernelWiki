### What does the DeepSeek-style MQA indexer compute before top-k?

**Card:** `indexer-mqa-score-semantics` · **Type:** `semantic` · **Evidence:** `source_observed`

**Axes:** `score_semantics`, `numerical_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>triton</code>, <code>flydsl</code>, <code>gluon</code>

#### Use when

- The workload uses weighted, rectified MQA logits over a per-query KV window.

#### Try

- Preserve logits[m,n] = sum_h ReLU(dot(Q[m,h,:], K[n,:]) * kv_scale[n]) * weights[m,h].
- Keep rectification before the head reduction and preserve the signed head weights and KV scale placement.
- Validate selected indices after top-k as well as score error; small score changes near the cutoff may change the sparse attention input.

#### Rationale

- The Triton score kernel performs the dot, KV scaling, ReLU, per-head weighting and reduction without softmax or a value projection.

#### Keep as alternatives

- Use a direct FP32 scoring expression and top-k over the same valid window as a reference.

#### Other implementations

- **flydsl** — The host API supplies the same Q, KV, scales, weights and row windows to explicitly selected kernel variants. [aiter_b3ad6c46:src_744823ffb69cb339](source_evidence.md#aiter_b3ad6c46-src_744823ffb69cb339)

### Which FP8 format conversions does the contiguous FlyDSL MQA logits path require?

**Card:** `indexer-fp8-architecture-format` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `numerical_contract`, `implementation_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>flydsl</code>
- `gfx`: <code>gfx942</code>, <code>gfx950</code>

#### Use when

- The selected path is flydsl_fp8_mqa_logits on gfx942 or gfx950.

#### Try

- On gfx950, respect the wrapper's native e4m3fn Q/KV requirement.
- On gfx942, keep the FN-to-FNUZ byte interpretation, negative-zero handling and compensating scale factor together; each FN operand contributes a factor of two.
- Retain the wrapper's contiguous Q/KV materialization and logical-rank restoration for single-token scales and weights.

#### Rationale

- The host wrapper explicitly distinguishes the two architectures and adjusts kv_scales consistently with operand recasting.

#### Keep as alternatives

- Use a native-format path or an explicit higher-precision reference before attempting a byte reinterpretation.

### Who initializes logits outside each query's valid window?

**Card:** `indexer-window-and-clean-output` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `score_semantics`, `selection_contract`, `implementation_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>flydsl</code>, <code>triton</code>

#### Use when

- The score buffer may be consumed by top-k over a larger allocated row.

#### Try

- Preserve the half-open [cu_starts, cu_ends) validity interval and mask the tail.
- With clean_logits=True the FlyDSL kernel writes negative infinity outside the window; with False the caller owns the skipped positions.
- Never feed uninitialized or stale out-of-window values into a selector that does not independently honor the same bounds.

#### Rationale

- The public FlyDSL API makes output cleaning an explicit behavior flag rather than an unconditional prefill of the output tensor.

#### Keep as alternatives

- Initialize invalid scores explicitly, or use a selector with verified matching row bounds.

#### Evidence

- [aiter_b3ad6c46:src_744823ffb69cb339](source_evidence.md#aiter_b3ad6c46-src_744823ffb69cb339) — [aiter/ops/flydsl/fp8_mqa_logits_kernels.py:470-614](https://github.com/ROCm/aiter/blob/b3ad6c461703110dc36286265c16e453ef0e2dd2/aiter/ops/flydsl/fp8_mqa_logits_kernels.py#L470-L614).

#### Background

- [knowledge/operator/attention_indexer/README.md](../README.md)

#### Limits

- Skipping output cleaning is only valid when the downstream validity contract excludes those positions.

- `requires`: <code>paged_kv</code>

#### Use when

- The candidate targets build_pa_mqa_logits_fp4_module and its packed cache representation.

#### Try

- Keep packed Q/KV bytes, E8M0 scale indexing and physical block-table addressing aligned; head_dim is not the byte width of a packed row.

### How does MiniMax block scoring differ from per-token MQA logits?

**Card:** `indexer-minimax-page-max-score` · **Type:** `semantic` · **Evidence:** `source_observed`

**Axes:** `score_semantics`, `cache_layout`, `numerical_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>flydsl</code>
- `gfx`: <code>gfx950</code>

#### Use when

- The task is the MiniMax-M3 decode page-score implementation on gfx950.

#### Try

- Compute a maximum over the tokens in each page for each query/head feature, respecting the per-query causal cutoff.
- Keep the source's FP8-cache-to-BF16 widening before the BF16 dot when Q is BF16; rounding Q down changes the ranking contract.
- Match the page layout, supported dimensions and output score layout before choosing decode or prefill tiling.

#### Rationale

- The source uses token-major MFMA fragments so much of the page maximum is reduced within registers, with final lane reductions.

#### Keep as alternatives

- Use a reference that widens K to Q precision, scores each token and takes the page maximum.

### What must a top-k implementation preserve beyond score values?

**Card:** `indexer-topk-row-index-contract` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `selection_contract`, `implementation_contract`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>flydsl</code>

#### Use when

- A per-row selector converts scores into the indices consumed by sparse attention.

#### Try

- Validate effective row lengths, k, output index dtype and strides, and optional score outputs.
- For packed rows, preserve the convention that output indices are relative to row_starts, while plane_width bounds the launch geometry.
- Check tie behavior and padding explicitly for the selected implementation; a stable parameter in a wrapper signature is not proof that every fast path enforces stable ordering.
- For graph capture, initialize the split path's stream-local arrival state on the capture stream as documented by the wrapper.

#### Rationale

- The host wrapper validates tensor signatures, has packed-row inputs, and dispatches between one-workgroup and split implementations.

#### Keep as alternatives

- Compare against a reference top-k with an explicitly stated tie convention and row bounds.

### How does DCP top-k merge preserve rank ownership and physical KV slots?

**Card:** `indexer-dcp-merge-ownership` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `distributed_merge`, `selection_contract`, `cache_layout`

#### Applicability

- `operator_families`: <code>attention_indexer</code>
- `target_languages`: <code>flydsl</code>
- `requires`: <code>distributed_candidates</code>

#### Use when

- The selected implementation merges rank-major candidate scores for qlen=1 decode.

#### Try

- Keep gathered candidate columns in rank-major order: column // local_k identifies the owner rank.
- Pad unused score candidates with negative infinity, not zero; another rank's plane has no local index liveness signal.
- Provide int32 block tables, indices, indptr, staging and counts with the validated capacity; convert the owned winning logical tokens to physical cache slots.
- Respect the wave64 and qlen=1 restrictions and warm each compiled shape before graph capture.

#### Rationale

- The merge API documents positional ownership, and its validator checks dtype, dimensionality, rank range and output capacities.

#### Keep as alternatives

- Keep candidate gathering, global selection and rank-local packing as explicit stages while validating ownership.

#### Evidence
