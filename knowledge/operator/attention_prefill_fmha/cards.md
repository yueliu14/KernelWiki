### Which prefill path and phase actually benefit from an attention change?

`prefill-live-path-and-phase` · performance · evidence: **reported** · applies: lang all

**When:** A framework routes full attention separately from decode or recurrent-attention layers.
**Try:**
- Identify the actual full-attention callable and importing call sites in every worker; compare eligible backend flags without assuming the historical winner transfers.
- Specialize a zero-prefix path only behind its real prefix-length contract, preserving nonzero-prefix fallback and per-row causal masking.
- Measure serving with its actual prefill/decode mix and unchanged numerical contract.
**Why:** Historical reports found backend flags or short-chunk specialization useful on particular stacks, while isolated prefill gains translated weakly to a decode-heavy workload.
**Alternatives:** Keep the existing correct implementation as the baseline and fallback; compare changes on the same workload.
**Limits:** Do not infer a full-model speedup from an isolated prefill ratio. Small numerical changes can affect greedy token selection even when a loose local tolerance passes.
**Reported:**
- mixed: Historical reports found backend flags or short-chunk specialization useful on particular stacks, while isolated prefill gains translated weakly to a decode-heavy workload.
- mixed: Serving results are tied to the instrumented eligible prefill path; the final PR does not alter decode routing, and one non-repeating negative trial is retained.

### How must tiled forward attention preserve masking and online softmax normalization?

`attention-online-softmax-mask` · semantics · evidence: **source-only** · applies: lang triton/flydsl/gluon

**When:** The operation is scaled dot-product forward attention, with an explicit causal or noncausal contract.
**Try:**
- Carry the running maximum, exponential sum and output accumulator together across KV tiles; rescale prior contributions when the maximum changes.
- Apply sequence-tail and causal masks to scores before exponentiation; a zero-filled invalid key is not an excluded softmax position.
- Keep QK scale, exponential base and accumulator precision consistent through the update and any final normalization.
**Why:** The Triton prefill kernel updates m_i, l_i and acc jointly, masks invalid scores with negative infinity, and casts probabilities to the value dtype before the PV dot.
**Alternatives:** Retain a straightforward unfused reference for the same mask and scale contract.
**Limits:**
- This softmax recurrence does not describe gated-delta or other recurrent attention.
- An all-masked row needs an explicitly validated convention; the cited prefill body is not proof that every empty-row input is supported.
**Reported:**
- gain reported: The final optimization elides masks only on fully visible prefill tiles; benchmark and revalidation revisions are separately recorded.
**Read more:** [README.md](README.md), [README.md](../gqa_mqa_attention/README.md)

### Which coupled decisions should be explored when changing attention tile sizes?

`attention-query-kv-tile-pipeline` · performance · evidence: **source-only** · applies: lang triton/gluon/flydsl

**When:** Correct forward attention already exists and the next candidate changes query/KV tile geometry or buffering.
**Try:**
- Consider query rows, KV tile width, head dimensions, waves and shared-memory buffering as a coupled resource bundle.
- Compare the single-buffer and standard attention-loop precedents with the same mask and cache layout.
- Retain tail masking and per-query normalization state when changing the amount of work per program.
**Why:** The Gluon unified implementation exposes distinct attention-loop buffering structures; the Triton prefill source exposes BLOCK_M/BLOCK_N.
**Alternatives:** Retain the simpler single-buffer or current tiling as a candidate.
**Limits:**
- Source structure alone gives no preferred tile or pipeline depth.
- The gfx950 Gluon precedent is not a claim of support on another architecture.
**Existing implementations:** gluon: Separate single-buffer and standard loops make the buffering choice explicit.
