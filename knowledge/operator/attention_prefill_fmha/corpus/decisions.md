### How must tiled forward attention preserve masking and online softmax normalization?

**Card:** `attention-online-softmax-mask` · **Type:** `semantic` · **Evidence:** `source_observed`

**Axes:** `attention_semantics`, `numerical_contract`

#### Applicability

- `operator_families`: <code>attention_prefill_fmha</code>, <code>gqa_mqa_attention</code>
- `target_languages`: <code>triton</code>, <code>flydsl</code>, <code>gluon</code>

#### Use when

- The operation is scaled dot-product forward attention, with an explicit causal or noncausal contract.

#### Try

- Carry the running maximum, exponential sum and output accumulator together across KV tiles; rescale prior contributions when the maximum changes.
- Apply sequence-tail and causal masks to scores before exponentiation; a zero-filled invalid key is not an excluded softmax position.
- Keep QK scale, exponential base and accumulator precision consistent through the update and any final normalization.

#### Rationale

- The Triton prefill kernel updates m_i, l_i and acc jointly, masks invalid scores with negative infinity, and casts probabilities to the value dtype before the PV dot.

#### Keep as alternatives

- Retain a straightforward unfused reference for the same mask and scale contract.

#### Limits

- This softmax recurrence does not describe gated-delta or other recurrent attention.

### Which coupled decisions should be explored when changing attention tile sizes?

**Card:** `attention-query-kv-tile-pipeline` · **Type:** `performance_candidate` · **Evidence:** `source_observed`

**Axes:** `kv_partition`, `compute_schedule`, `data_movement`

#### Applicability

- `operator_families`: <code>attention_prefill_fmha</code>, <code>attention_decode_paged</code>
- `target_languages`: <code>triton</code>, <code>gluon</code>, <code>flydsl</code>

#### Use when

- Correct forward attention already exists and the next candidate changes query/KV tile geometry or buffering.

#### Try

- Consider query rows, KV tile width, head dimensions, waves and shared-memory buffering as a coupled resource bundle.
- Compare the single-buffer and standard attention-loop precedents with the same mask and cache layout.
- Retain tail masking and per-query normalization state when changing the amount of work per program.

#### Rationale

- The Gluon unified implementation exposes distinct attention-loop buffering structures; the Triton prefill source exposes BLOCK_M/BLOCK_N.

#### Keep as alternatives

- Retain the simpler single-buffer or current tiling as a candidate.

#### Other implementations

- **gluon** — Separate single-buffer and standard loops make the buffering choice explicit.
