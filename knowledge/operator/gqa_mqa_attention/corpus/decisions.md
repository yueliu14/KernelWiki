### How should query heads share KV heads without changing GQA/MQA semantics?

**Card:** `attention-gqa-head-mapping` · **Type:** `semantic` · **Evidence:** `source_observed`

**Axes:** `attention_semantics`, `cache_layout`

#### Applicability

- `operator_families`: <code>gqa_mqa_attention</code>, <code>attention_decode_paged</code>
- `target_languages`: <code>triton</code>, <code>gluon</code>, <code>flydsl</code>

#### Use when

- The workload has more query heads than KV heads.

#### Try

- Preserve the query-head-to-KV-head mapping and the required divisibility when grouping query heads into a workgroup.
- Treat query-head grouping as a reuse opportunity; tune the group and tile sizes while retaining each query head's separate normalization state.
- Check unequal query/KV head counts and nontrivial strides, not only ordinary equal-head MHA.

#### Rationale

- The unified kernel separates query head indexing from KV-head indexing while carrying per-query softmax state.

#### Keep as alternatives

- One independent query head per program is a simple baseline for the same shared KV cache.

- `operator_families`: <code>gqa_mqa_attention</code>
- `target_languages`: <code>triton</code>, <code>gluon</code>, <code>flydsl</code>, <code>hip</code>, <code>ck</code>, <code>asm</code>, <code>tilelang</code>

#### Use when

- KV traffic is limiting and the accepted accuracy contract permits a storage-precision experiment.

#### Try

- Separate storage, conversion and dot/accumulation dtypes; derive packed K addressing from element size and validate scale/layout compatibility.
- Gate QK, softmax probabilities and PV precision changes independently, including near-cancellation outputs and model accuracy.
- Re-measure cache residency and occupancy after the byte footprint changes.

#### Rationale

- Some historical attention cases benefited from FP8 KV storage with wider in-register computation, while narrowing a different dot or intermediate failed its accuracy gate.

#### Keep as alternatives

- Keep the existing correct implementation as the baseline and fallback; compare changes on the same workload.
