### Can a gated-delta contraction share head work or hoist a scale?

`gated-delta-factorable-scale-and-head-reuse` · performance · evidence: **reported** · applies: lang all

**When:** The scale is provably independent of the reduced axis and grouped heads share the same contracted operand.
**Try:**
- Derive the factorization and preserve gate/scale placement relative to casts and accumulation; compare with an independent numerical reference.
- Share common contraction work across compatible heads while retaining their separate epilogues and outputs.
- Re-tune resource use and evaluate the combined chain after each hoist or head-packing change.
**Why:** A historical contraction benefited from shorter load-to-dot chains and shared head work, but overlapping changes did not add independently.
**Alternatives:** Keep the existing correct implementation as the baseline and fallback; compare changes on the same workload.
**Limits:** Do not remove zero stores unless the public output-initialization contract guarantees them. A harness-prezeroed buffer is not sufficient.
**Reported:**

**Alternatives:** Keep the existing correct implementation as the baseline and fallback; compare changes on the same workload.
**Limits:** Write-once within one kernel is not sufficient: a following stage can reuse the output immediately. Cache modifiers are backend- and architecture-specific.

### What state and index contracts distinguish gated-delta decode from softmax attention?

`attention-gated-delta-state-contract` · constraint · evidence: **source-only** · applies: lang flydsl/gluon

**When:** The workload executes the recurrent gated-delta decode path.
**Try:**
- Preserve the distinction between read_indices and write_indices; both default to indices but may designate different state slots.
- Respect the state alignment, dtype and Q/K last-dimension stride checks; use need_shuffle_state only with its corresponding layout conversion.
- Validate the updated recurrent state as well as the visible output, including multi-step execution and state-slot reuse.
**Why:** flydsl_gdr_decode explicitly validates index dtypes and state layout before selecting its tiling and launching the recurrent update.
**Alternatives:** Use the unfused recurrent state update as a correctness reference; evaluate prefill/chunk implementations separately.
**Limits:**
- Softmax KV-split reduction is not an implementation of this recurrence.
- A one-step output match does not verify the next token's state.
**Reported:**
- mixed: PR #4907 extends GDN state updates to MTP chains and draft trees. Kernel aggregates, the early synchronization regression and the later public-entry improvement have separate evidence.
