### What state and index contracts distinguish gated-delta decode from softmax attention?

**Card:** `attention-gated-delta-state-contract` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `recurrent_state`, `implementation_contract`

#### Applicability

- `operator_families`: <code>linear_attention_gated_delta</code>
- `target_languages`: <code>flydsl</code>, <code>gluon</code>

#### Use when

- The workload executes the recurrent gated-delta decode path.

#### Try

- Preserve the distinction between read_indices and write_indices; both default to indices but may designate different state slots.
- Respect the state alignment, dtype and Q/K last-dimension stride checks; use need_shuffle_state only with its corresponding layout conversion.
- Validate the updated recurrent state as well as the visible output, including multi-step execution and state-slot reuse.

#### Rationale

- flydsl_gdr_decode explicitly validates index dtypes and state layout before selecting its tiling and launching the recurrent update.

#### Keep as alternatives

- Use the unfused recurrent state update as a correctness reference; evaluate prefill/chunk implementations separately.
