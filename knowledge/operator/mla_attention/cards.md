How to read a card:
- **Evidence** — `reported`: an upstream PR or benchmark reported an outcome (not reproduced here; the outcome
  line says what was reported). `source-only`: observed in shipped source or configs; it shows what an
  implementation does, not that it wins. Treat both as hypotheses and measure on your own kernel and shapes.
- **Applies** — the languages/dtypes/GPUs the card was derived from. For a kernel in another language the card is a
  porting idea, not a recipe.
- `constraint` cards are correctness or validity rules: check them before trusting a speedup.

### Which tensor and mapping invariants does the FlyDSL MLA reducer require?

`attention-mla-reduce-abi` · constraint · evidence: **source-only** · applies: lang flydsl

**When:** The selected path calls flydsl_mla_reduce_v1 with mapped partial outputs.
**Try:**
- Use FP32 partial_output [rows,H,Dv] and partial_lse [rows,H], int32 mapping/indptr arrays, and a common GPU device.
- Provide a 3D BF16/FP16 final output with packed last dimension and matching H/Dv; validate optional final LSE and final-map tensors too.
- Pass only valid split counts and map bounds, and preserve the difference between allocated maximum splits and actual splits.
**Why:** The host validator checks dtype, rank, strides, shape relationships and split metadata before raw pointers reach the kernel.
**Alternatives:** Convert layouts explicitly at the boundary, accounting for their cost, or select a reducer that natively accepts the producer layout.
**Limits:**
- These are the cited reducer's requirements, not a universal MLA ABI.
- A dtype-correct mapping can still point at the wrong sequence; validate mapping contents.
**Reported:**
- gain reported: The complete FlyDSL mapped-LSE reducer has reported graph-replay and serving gains; the partial layout and normalization contract remain mandatory.

### When splitting KV work, what information must the merge preserve?

`attention-split-kv-merge` · performance · evidence: **source-only** · applies: lang triton/flydsl/gluon

**When:** A long KV sequence leaves too few independent query/head workgroups, or partial attention outputs already exist.
**Try:**
- Try multiple KV partitions together with an explicit partial-output and normalization-statistics layout.
- Merge partials using their maxima and exponential sums, or the equivalent LSE representation; never take an unweighted average of already-normalized partial outputs.
- Include the merge and scratch traffic when assessing a split count, and mask unused partitions.
- Test the split/merge path at one partition as a control, then validate each split count against the unchanged accepted reference and an independent high-precision diagnostic.
- Check cancellation-sensitive and near-zero outputs; distinguish agreement with the golden implementation from mathematical accuracy.
**Why:** The Triton MLA reduce kernel rescales segment sums and outputs by exp2(segment_max - overall_max), then divides by the combined exponential sum.
**Alternatives:** Keep an unsplit path for short contexts or sufficiently large query batches.
**Limits:**
- The source demonstrates local segment merging, not an implementation of cross-rank transport; context-parallel ownership and communication require separate evidence.
- The cited raw-max/exp-sum representation cannot be mixed directly with another backend's LSE ABI.
- A diagnostic reference does not authorize weakening or replacing the required oracle. A precision change needs an explicitly accepted numerical/task-accuracy contract.
**Reported:**
- constraint: Historical attention reports found reduction reassociation and lower-precision KV could fail the existing gate even when an alternative was closer to a high-precision diagnostic.
- gain reported: The complete FlyDSL mapped-LSE reducer has reported graph-replay and serving gains; the partial layout and normalization contract remain mandatory.
**Existing implementations:** flydsl: The FlyDSL reducer consumes partial outputs, partial LSE and explicit partial/final maps; its host validator defines a separate ABI.
