### Does decode use split metadata for the attended window or for the full context?

`window-specific-split-metadata` · performance · evidence: **reported** · applies: lang all

**When:** A sliding-window decode path carries separate full-context and window-local KV metadata.
**Try:**
- Trace the split-count tensor through eager initialization, graph updates and the final launch; select the metadata corresponding to the attended KV domain.
- Validate both sliding and full-attention layers plus short/long contexts when changing the split cap.
**Why:** A historical serving report found window-local split metadata was prepared but not consumed by the decode launch; a global cap also harmed a different regime.
**Alternatives:** Keep the existing correct implementation as the baseline and fallback; compare changes on the same workload.
**Limits:** The reported framework bug and flags are revision-specific. A fixed split count is not a universal window-attention setting.
**Reported:**

### How do cached prefixes and sliding windows change the causal boundary?

`attention-window-prefix-boundaries` · constraint · evidence: **source-only** · applies: lang triton/gluon/flydsl

**When:** Queries cover only a suffix/chunk, or the model restricts each query to a local attention window.
**Try:**
- Express the causal boundary in logical sequence coordinates including the cached prefix; do not substitute the query tile's local row number.
- Intersect the sliding window, causal boundary and actual sequence length before dropping KV tiles.
- Preserve the unified kernel's restriction that SPLIT_UNMASKED_LOOP is incompatible with sliding-window attention.
**Why:** The extend kernel distinguishes prefix/cache work from extension work; unified attention separately prunes window tiles and asserts the loop restriction.
**Alternatives:** Retain per-element score masking while first validating any tile-pruning optimization.
**Limits:** An optimization for fully valid KV tiles is not valid for every prefix/window boundary.

**When:** The selected implementation matches the cited path and its input contract.
**Try:**
- Check the wrapper eligibility predicate with windowing and all other active features, not just the GPU name.
- At this snapshot the gfx950 Gluon predicate excludes softcap, QQ bias and ALiBi; it also constrains head widths, Q/cache dtypes and shuffled-cache block geometry.
- Preserve an applicable alternate backend when a feature combination does not satisfy the predicate.
**Why:** The cited source declares these operations and checks; the combination is part of its interface.
**Alternatives:** Keep a simpler implementation with the identical numerical and layout contract for comparison.
**Limits:**
- A wrapper eligibility predicate is version-specific and is not a hardware impossibility claim.
- This predicate does not replace checking the per-query sliding-window bounds.
