### How do cached prefixes and sliding windows change the causal boundary?

**Card:** `attention-window-prefix-boundaries` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `attention_semantics`, `kv_partition`

#### Applicability

- `operator_families`: <code>sliding_window_attention</code>, <code>chunked_prefill</code>, <code>attention_prefill_fmha</code>
- `target_languages`: <code>triton</code>, <code>gluon</code>, <code>flydsl</code>

#### Use when

- Queries cover only a suffix/chunk, or the model restricts each query to a local attention window.

#### Try

- Express the causal boundary in logical sequence coordinates including the cached prefix; do not substitute the query tile's local row number.
- Intersect the sliding window, causal boundary and actual sequence length before dropping KV tiles.
- Preserve the unified kernel's restriction that SPLIT_UNMASKED_LOOP is incompatible with sliding-window attention.

#### Rationale

- The extend kernel distinguishes prefix/cache work from extension work; unified attention separately prunes window tiles and asserts the loop restriction.

#### Keep as alternatives

- Retain per-element score masking while first validating any tile-pruning optimization.
