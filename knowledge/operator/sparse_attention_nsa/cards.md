### Which sparse-attention partition should be tuned without changing selected-slot semantics?

`sparse-prefill-block-subtiling` · performance · evidence: **reported** · applies: lang all

**When:** The implementation consumes selected KV blocks with explicit per-query masks and separate prefill/decode entry points.
**Try:**
- Tune KV-block subtiles and MFMA launch parameters by architecture while preserving block indices, real-top-k bounds and per-row causal masks.
- Treat query packing as a separate experiment rather than assuming it caused a reported sub-tiling gain.
- Validate partial prefill chunks and the full serving path independently of decode.
**Why:** An earlier report proposed query packing; a later report attributed the useful prefill change to KV-block sub-tiling instead.
**Alternatives:** Keep the existing correct implementation as the baseline and fallback; compare changes on the same workload.
**Limits:** A backend unavailable in an old stack may exist in a newer one. Preserve the sparse math contract when comparing candidates.
**Reported:**
- mixed: An earlier report proposed query packing; a later report attributed the useful prefill change to KV-block sub-tiling instead.

### What distinguishes sparse selected-slot attention from dense paged attention?

`attention-sparse-selected-slots` · constraint · evidence: **source-only** · applies: lang triton/gluon/flydsl

**When:** An upstream indexer supplies selected KV indices or slots for each query.
**Try:**
- Keep the selected-slot representation, valid count and sentinel convention aligned with the cache lookup.
- Mask invalid selected entries before loading cache data and before softmax; do not reinterpret sparse-list positions as logical token IDs.
- Validate repeated, missing and boundary indices according to the producer contract before tuning gather or LDS staging.
**Why:** The sparse MLA implementations explicitly load selected slots and perform sparse gathers rather than iterating a dense KV range.
**Alternatives:** Use a reference that gathers the same selected indices and computes attention over that set.
**Limits:** This card does not establish indexer ranking correctness or a policy for duplicate selections.
**Existing implementations:** gluon: The sparse MLA path isolates slot loading and cache gather helpers before its compute path.
