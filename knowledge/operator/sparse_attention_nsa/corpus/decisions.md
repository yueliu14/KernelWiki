### What distinguishes sparse selected-slot attention from dense paged attention?

**Card:** `attention-sparse-selected-slots` · **Type:** `constraint` · **Evidence:** `source_observed`

**Axes:** `sparse_selection`, `cache_layout`

#### Applicability

- `operator_families`: <code>sparse_attention_nsa</code>
- `target_languages`: <code>triton</code>, <code>gluon</code>, <code>flydsl</code>

#### Use when

- An upstream indexer supplies selected KV indices or slots for each query.

#### Try

- Keep the selected-slot representation, valid count and sentinel convention aligned with the cache lookup.
- Mask invalid selected entries before loading cache data and before softmax; do not reinterpret sparse-list positions as logical token IDs.
- Validate repeated, missing and boundary indices according to the producer contract before tuning gather or LDS staging.

#### Rationale

- The sparse MLA implementations explicitly load selected slots and perform sparse gathers rather than iterating a dense KV range.

#### Keep as alternatives

- Use a reference that gathers the same selected indices and computes attention over that set.
