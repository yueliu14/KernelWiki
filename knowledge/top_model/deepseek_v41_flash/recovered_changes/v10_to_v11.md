## DSpark Markov sampling on gfx950

TP selector: `None` (`None` means all configurations reviewed on this edge).

**Before:** V09 uses ordinary sampling; V10 contains a fused helper whose architecture guard admits gfx942 only.

**After:** V11 guard admits gfx950; exact endpoint logs report five steps, vocabulary 129280, rank 256, 505 blocks.

**Device language:** Triton sampling core; separate base-logit GEMM

**Body change:** The per-step kernel loads the previous token via prior block maxima, computes Markov bias plus base logits and block Gumbel-max. Final kernel resolves the last token. The info message is emitted after eligibility checks and before launches.

**Fusion:** Sampling core uses five per-step kernels plus one final resolver. Base-logit computation, input gathers and scratch initialization are outside this count. There is no single launch covering all five sequential steps.

**Applicability / log limit:** gfx950 --monokernel, at most five request rows, supported sampler/dtypes. All observed first Markov messages precede E2E measurement; they do not prove sustained coverage at higher concurrency.
