### AMD Muse layer monokernel

**Before:** Ordinary SGLang attention, projection, routing, experts, residual/norm and collective launches. The monokernel interface alone does not activate the plugin.

**After:** runtime → Muse spec → Runner.launch → build_layer; eligible MXFP4 layers combine attention, K2, K3 and the next eligible layer K1.

**Device language:** Mixed Triton/FlyDSL/library path → FlyDSL layer kernel (the log/spec name muse_spark_hip does not identify the implementation language).

**Code/body change:** Device mailbox flags connect producer/consumer stages; one launch reuses stage LDS while retaining scratch regions. The first necessary K1 and BF16-expert layers keep separate execution.

**Fusion:** Merge attention, output norm/gate and projection/reduction, routing/pooler/top-k, experts/finalize/reduction, unpooler/boundary and next-layer QKV preparation across host launch boundaries. Scratch traffic is not assumed eliminated.

**Applicability to this pair:** Both endpoint CLI logs are checked: only the new endpoint passes monokernel-backend=amd. TEP8/EP8 with 8-token DFLASH; one admitted request corresponds to 8 verify rows and two to 16. Unsupported shapes, prefill and BF16-expert layers use fallback. ### Ordinary verify merge with output norm/gate

**Before:** The attention partials are merged, then the existing output norm-gate kernel runs.

**After:** VerifyReduceDeferral hands partials to forward_verify_partials → _reduce_norm_gate.

**Device language:** Triton → Triton.

**Code/body change:** The new body reads partials/maxima/denominators, performs split-KV reduction, rounds to BF16, and applies per-head RMSNorm and sigmoid gate before the output store.

**Fusion:** One reduce+norm+gate launch replaces separate merge and norm-gate launches; removes the completed-attention intermediate between those launches.

**Applicability to this pair:** Ordinary target-verify path, head_dim 64, output normalization enabled, and backend deferral active. On monokernel-covered MXFP4 layers the layer kernel supersedes this path; retain this candidate only for ordinary/fallback layers.

### Residual/norm boundary with FP8 output

**Before:** The fused boundary yields a BF16 attention input and residual stream.

**After:** forward_fp8 can additionally write the next projection input as FP8 plus per-row scales.

**Device language:** Triton → Triton.

**Code/body change:** The boundary kernel gains output/scaling buffers and a guarded FP8 output path; native fallback can still perform separate quantization.

**Fusion:** For its fused Triton branch, quantization is part of the norm/boundary producer, saving a separate read/quantize launch.

**Applicability to this pair:** Ordinary path when the model requests fp8_out/forward_fp8; do not transfer this benefit to the monokernel-covered layers without a trace.
