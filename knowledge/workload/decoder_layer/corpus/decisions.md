## When must a fused layer keep a launch boundary for cache publication?

`layer-preserve-cache-publication-boundary` · candidate only · fusion_boundary, synchronization, data_lifetime

### Use when

- A front stage writes KV records that the attention consumer reads across producer workgroups.
- The target uses the documented gfx950 K1/K2 organization and cache representation.

### Actions

- Keep the K1-to-K2 ordering until a replacement explicitly supplies publication, visibility and progress guarantees for every consumer.
- Review cache readers and memory scopes before combining the launches; account for the conditional indexer work between them.

### Rationale

- The pinned spec assigns device-wide release to the launch boundary; the live caller invokes K1 before K2.

### Alternatives

- Retain staged execution as a correctness baseline.
- Design and separately validate an in-kernel handoff for the target memory hierarchy.

## How should launch accounting include an indexer between fused layer stages?

`layer-count-conditional-indexer-work` · candidate only · fusion_boundary, dispatch, measurement

### Use when

- The layer can use a compressed/indexed KV source or a window-only path.

### Actions

- Record K1, conditional compressor/index-query/K2i/selection work, and K2 as separate execution boundaries.
- Resolve identity, full, producer and reindex branches for the actual rows and context before counting launches.
- Keep logits, metadata, copies and end-of-stack gathers outside the core count but inside full-step measurement.

### Rationale

- Two core launches do not imply two total device launches for an index-source layer or a complete serving step.

### Alternatives

- Report a branch-conditioned launch sequence without inventing a fixed total.

## When can a layer defer its residual update into the next consumer?

`layer-deferred-residual-ownership` · candidate only · data_lifetime, fusion_boundary, numerical_contract

### Use when

- A consumer understands the pending output, residual, post/combine and pre-mix representation.

### Actions

- Represent pending versus settled residuals explicitly and apply the post update exactly once.
- Respect the first-layer, Engram and final-head boundaries; retain captured auxiliary hidden states and token-parallel row ownership.

### Rationale

- The forward carries pending state between layers and settles it when a consumer requires the ordinary representation.

### Alternatives

- Materialize each residual update before calling the next layer.

### Evidence and assessment
